# Оффер на NFT-подарок из чата (userbot)

Один процесс, `owner_session.py`. Он работает под вашим аккаунтом Telegram и ничего никому не отправляет: ни клиентам, ни боту. Бот не нужен, потому что оффер за подарок может отправить только пользовательский аккаунт (`payments.sendStarGiftOffer`). Bot API этого не умеет.

## Как пользоваться

1. Откройте личный чат с человеком, у которого есть подарок.
2. Напишите одну строку: кодовое слово, ссылка на подарок и цена в звёздах. Порядок любой:
   ```
   апельсин https://t.me/nft/SignetRing-4557 500
   ```
3. Процесс удаляет это сообщение у обеих сторон и отправляет оффер на 500 ⭐.

Оффер уходит, только если подарок принадлежит собеседнику. Если владелец другой, оффер не отправляется, а сообщение всё равно удаляется. Сообщение с кодовым словом, но в неверном формате, тоже удаляется, и оффер не отправляется.

Команду может написать только вы, сообщения от собеседника с этим словом игнорируются.

Результат виден в логах процесса и в самом чате: отправленный оффер появляется там как системное сообщение. Ошибки в чат не приходят, поэтому смотрите логи.

## Входящие предложения

Когда клиент предлагает звёзды за ваш подарок, процесс решает по порогам из `.env`:
- сумма ≥ `OFFER_ACCEPT_MIN_STARS` → принимает;
- сумма < `OFFER_DECLINE_BELOW_STARS` → отклоняет;
- иначе ничего не делает, решаете вы до истечения срока.

Если пороги не заданы, процесс только пишет в лог. Решение принимается по цене из системного сообщения Telegram, а не по тексту клиента.

## Установка через терминал

Нужны `git` и Python 3.10+ (на Debian/Ubuntu: `sudo apt install git python3 python3-venv`).

Сначала получите `api_id` и `api_hash` на https://my.telegram.org → API development tools.

Вариант 1, клонировать и установить:
```bash
git clone https://github.com/gytfel/Tg-ref.git tg-gift-bot && cd tg-gift-bot && ./install.sh
```

Вариант 2, одной командой (если репозиторий публичный):
```bash
curl -fsSL https://raw.githubusercontent.com/gytfel/Tg-ref/main/install.sh | bash
```
Проект ставится в `~/tg-gift-bot` (поменять: `INSTALL_DIR=/путь`).

`install.sh` создаёт `.venv`, ставит зависимости, прогоняет тесты и по шагам спрашивает значения для `.env`. Повторный запуск безопасен: `.env` не перезаписывается.

Запуск:
```bash
./run.sh
```
При первом запуске он спросит номер телефона, код из Telegram и пароль 2FA, если он включён. Сессия сохранится в файл `TG_SESSION`, и повторный вход не понадобится.

Работа в фоне на Linux-сервере (после первого входа через `./run.sh`):
```bash
./install.sh --service
journalctl --user -u tg-gift-bot -f   # логи
```

Проверьте на маленькой сумме: напишите команду в чате с другим аккаунтом и посмотрите лог.

Тесты без сети:
```bash
.venv/bin/python -m unittest tests.test_logic tests.test_owner_session
```

## Риски и ограничения

- **Файл сессии даёт полный доступ к аккаунту.** Не публикуйте его, не коммитьте в git и не запускайте процесс на чужих машинах. Если он утёк, завершите все сессии в Telegram: Settings → Devices.
- **Автоматизация личного аккаунта** может привести к ограничениям со стороны Telegram. Для личного использования с умеренными объёмами это обычно работает, но риск есть.
- **Оффер связан со звёздами.** Держите `OFFER_MAX_STARS` низким.
- **Собеседник может на долю секунды увидеть команду**, прежде чем процесс её удалит. Процесс видит сообщение только после отправки.
- **Удаление может не сработать**, если у сообщения нет нужных прав. Тогда оффер всё равно отправляется, а сообщение остаётся в чате. Причина пишется в лог.
- **Список диалогов загружается при старте.** Если аккаунт очень большой, старт займёт заметное время.
- **Кеш обработанного в памяти.** После перезапуска дубль возможен, поэтому не отправляйте одну команду дважды.
- **Живой Telegram не проверен.** Из моей среды нет доступа к api.telegram.org. Тесты и смоделированные обновления проходят, но первый запуск делайте с небольшой суммой.
